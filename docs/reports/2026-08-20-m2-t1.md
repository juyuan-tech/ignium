# M2 T1 完成报告:用户态线程 + ecall 系统调用

## 1. 摘要

完成 M2 里程碑 T1:用户态线程执行、ecall 系统调用往返、线程退出。在 QEMU virt 上验证。

## 2. 发现明细

### 2.1 Bug 1:中间级 PTE 误置 U 位 → U 模式取指指令页故障(scause=0xc)
- **严重度**:致命(blocking)
- **位置**:`kernel/src/mmu.rs:ensure_table_user`
- **触发条件**:创建用户页表入口时,`ensure_table_user` 给中间级(非叶子)PTE 设置了 `PTE_V | PTE_U`。
- **影响**:U 模式取指时 QEMU 8.2 的 `get_physical_address` 检查中间级 PTE 的 U/A/D 位,发现非零直接返回 `TRANSLATE_FAIL`,导致 scause=0xc(instruction page fault)。
- **根因**:RISC-V Sv39 规范要求中间级 PTE(表指针)只允许 V 位,R/W/X/U/A/D 必须为 0;QEMU 严格实现。

### 2.2 Bug 2:用户线程 exit 导致 timer 中断永久失效(sscratch 残留)
- **严重度**:致命(blocking,`make test` uptime 断言失败)
- **位置**:`kernel/src/sched.rs:exit` → `context_switch`
- **触发条件**:用户线程通过 ecall(EXIT)从 trap 上下文调用 `sched::exit()`。`exit()` 用 `context_switch` 切回主线程,但 `context_switch` 不重置 `sscratch` CSR。`sscratch` 残留为本次 trap 的帧底值。
- **影响**:主线程恢复后,下次 timer 中断进入 `trap_vector`,嵌套检测(汇编 label `4`)发现 `sscratch` 不等于 `_trap_stack_top - TRAP_FRAME_SIZE`,误判为"第二层 trap"而停机。系统卡在 `wfi` 死循环,ISR 永不触发,uptime 停止。
- **根因**:`exit()` 路径假设调用者在线程栈上(thread_entry 返回),但用户线程 ecall 中断从陷阱栈调用。`context_switch` 的语义不适合从 trap 上下文切换(缺乏 sscratch 维护)。

### 2.3 Bug 3:用户程序 syscall 号误用 a0 而非 a7
- **严重度**:高(功能错误)
- **位置**:`kernel/src/main.rs` boot 测试用户程序编码
- **触发条件**:用户程序 `addi a0, x0, 2` 将 syscall 号放在 a0,但 `syscall::handle` 按 RISC-V 约定读取 a7。
- **影响**:syscall 分发落到未知号分支,返回 `-ENOSYS`。

### 2.4 Bug 4:boot 用户程序 `sw a0, 0(t0)` 编码错误
- **严重度**:高(功能错误)
- **位置**:`kernel/src/main.rs` 用户程序编码 `0x0a2a_0023`(应为 `0x00a2_a023`)
- **触发条件**:存储指令编码错误(rs2 字段错位),写入共享页时实际存储错误寄存器。

## 3. 修复明细

### 3.1 中间级 PTE U 位修复
- **文件**:`kernel/src/mmu.rs`
- `ensure_table_user`:中间级表项从 `pte(page, PTE_V | PTE_U)` 改为 `pte(page, PTE_V)`(仅 V 位)。
- `map_user_page`:leaf flags 仍 `| PTE_U`(用户访问权限由叶子决定)。
- 文档注释同步更新,阐述规范与 QEMU 行为。

### 3.2 sscratch 残留修复(exit_from_trap)
- **文件**:`kernel/src/sched.rs` + `kernel/src/arch/riscv64.rs`
- 新增 `pub fn exit_from_trap()`:与 `exit()` 类似,但在切换前调用 `arch::set_sscratch_trap_top()` 重置 sscratch 为陷阱栈顶,再 context_switch 到目标线程。
- 新增 `pub fn set_sscratch_trap_top()`:内联汇编加载 `_trap_stack_top` 符号写入 `sscratch` CSR。
- `trap_handler` 的 ecall 分支:对 `SYSCALL_EXIT` 调用 `exit_from_trap()` 而非 `exit()`。

### 3.3 用户程序编码修复
- **文件**:`kernel/src/main.rs`
- syscall 号改用 a7: `addi a7, x0, 2` / `addi a7, x0, 1`。
- `sw` 指令修正为 `0x00a2_a023`。

### 3.4 其他改进
- `mmu.rs`:新增 `KERNEL_ROOT` 记录 + `kernel_root()` 导出,供 M2 API 参照。
- `map_user_page`:新增 `sfence.vma` 确保映射立即可见。
- `sched.rs`:新增 `spawn_user` + `user_entry_stub`,用户线程框架。
- `syscall.rs`:新模块,按 a7 分发,支持 `SYSCALL_GET_TICKS`/`SYSCALL_EXIT`。

## 5. 遗留风险
- **用户线程没有独立地址空间**:当前映射在**内核页表**上,用户页 U=0 受保护,但同一地址空间。每进程页表(独立 satp)属 T2。
- **用户线程 spin 不自愿让出会饿死 idle**:当前协作调度器——用户忙循环(无 ecall)不释放 CPU。T2 需时间片抢占+M2 调度器。
- **syscall 表只有两个占位**:`linux/write/open` 等待 T2 实现。
- **仅单核**:副核在 entry.S park。多核需 D7/D8/D9。
- **用户线程无 ELF 加载器**:当前 boot 测试用手写机器码。T2 需 ELF 加载器。

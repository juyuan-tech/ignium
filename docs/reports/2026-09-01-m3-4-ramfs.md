## 1. 摘要

ROADMAP 阶段 3 的第三项 = **ramfs 文件系统服务(open/read/write/close)**(验收:IPC
客户端可读写删文件)。本轮引入**用户态 ramfs_server** 文件系统服务,交付指向
**「一切皆能力」**:内核**零新 syscall 号、零新 `Cap` 变体**(保持 Proc/Shm/Page),
文件/目录/名字全是 ramfs_server 服务内资源;文件句柄**绑定连接**(专用连接槽,无
全局 fd 命名空间)。

**用户已拍板(AskUserQuestion)**:
- 数据面 = **共享内存窗口**:客户端经现有 `shm_map` 与 ramfs_server 共享 4KB 缓冲
  (`Cap::Shm`),读写载荷经 SHM_VA,控制面(op+fd+len)走 5 字 IPC;
- 存储面 = **mem_server 服务链**:ramfs_server 是 mem_server 的客户端,经 IPC 申请
  `Cap::Page` 做文件数据页(申请 → mem_map → 读写 → 归还);
- 方向强调 **「更符合一切皆能力」** → 能力全程经服务 IPC 流动,无 ambient 分配。

## 2. 交付内容(对照设计)

### D1 数据面:客户端自建共享内存窗口(Cap::Shm)

- client 经 `connect(RAMFS,2,0) → cap_dup(2,3) → shm_map(3, server_slot=1, 4096)`
  建立窗口;ramfs_server 槽 1 = `Cap::Shm`。读写载荷经 `SHM_VA[0..n]`,控制经 IPC
  —— 复用 uart 已验证模式。
- 能力从客户端流向服务端(client 自持 Cap::Shm,服务端因被授予而访问)。

### D2 存储面:mem_server 服务链(Cap::Page 经 IPC 申请)

- ramfs_server 是 mem_server 客户端:open 建文件时 `send(2,[OP_ALLOC,...])` → 收
  `Cap::Page` 进文件页槽(3+fd)→ `mem_map` 至 `RAMFS_VA + fd*4096`;unlink 时
  `send(2,[OP_FREE,page_slot])` → 收 recv_slot → `mem_grant(page_slot, peer=2,
  recv_slot)` 归还(**移交隐含解除发送方映射**,D34)。
- 链:测试注入池 → mem_server → ramfs_server → ramfs_client;页面能力全程经服务
  IPC 流动,无 ambient 分配。

### D3 一切皆能力:零新 syscall、零新 Cap、fd 绑定连接

- 文件/目录/名字是 ramfs_server 服务内资源;fd 是文件页槽下标(槽 3..=6 → fd 0..3)。
- **文件句柄绑定连接**:ramfs_server 用槽 0 收请求(启动时空槽 = accept-any;client
  connect 后变特定接收,只收持 Cap::Proc(ramfs_server) 的 sender)—— 连接即能力,
  fd 无全局命名空间(单 client,D36)。

### D4 ramfs_server 用户态服务(user/src/bin/ramfs_server.rs)

- 槽位:`0` 连接槽、`1` SHM 窗(Cap::Shm)、`2` mem_server(Cap::Proc(mem_server))、
  `3..=6` 文件页槽(**fd = 槽-3**,Cap::Page)、`7` 备用。
- 文件表:`FileEntry { state: Free|Open|Closed, name:[u8;24], name_len, size }`,
  MAX_FILES=4。**create-or-reopen**:open 不存在名 → 建(分配页);存在且 Closed →
  重开(同 fd);Open → EEXIST。**close 保槽(Open→Closed),unlink 按 fd**(D40)。
- 五 op(回复首字 `op|0x80`、次字 status):OPEN(0x06) name_len/name×3 字 → fd;
  READ(0x07) fd/off/len → bytes_read(EOF → 0,非错误);WRITE(0x08) → bytes_written
  (载荷经 SHM_VA;offset 越界 → EINVAL);CLOSE(0x09);UNLINK(0x0A,经 OP_FREE +
  mem_grant 归还页)。
- errno 映射:坏 fd → **USER_ERR_EBADF=MAX-4**(复活保留隙,D39);offset 越界 →
  EINVAL;重复 open → EEXIST;表满/池空 → ENOMEM;未知 op → PROTO_ERR。
- 名字内联 IPC 3 字 = 24B;lib.rs `name_to_words`/`name_from_words` 成对助手(防
  端序错配;长名 D38)。

### D5 ramfs_client(user/src/bin/ramfs_client.rs)

- 流程:connect(RAMFS,2,0) → cap_dup(2,3) → shm_map(3,1,4096) → OPEN"test.txt"(收
  fd)→ **内联负面**(EOF 0 字节 / 重复 open EEXIST / fd=99 EBADF / off=4095 len=2
  EINVAL)→ WRITE"hello ramfs"(11B 经窗,校验 written=11)→ READ 回读逐字节比对 →
  CLOSE → UNLINK → 写 marker `0xC0DE_0000|argc` → sys_exit。任一断言失败 → 提前
  exit,marker 不到,测试侧 guard 超时断言失败(同 mem_client 模式)。

## 3. 实现中发现的设计缺口与修复

### F1(client 谓词槽位错位,运行时才暴露)—— 本轮唯一 bug

- **位置**:`user/src/bin/ramfs_client.rs`(`fs_request` 内联谓词)。
- **触发**:服务端回复帧为 `[op|0x80, status, result, 0, 0]` —— errno 在 **status
  槽(reply[1])**,载荷结果(fd/bytes)在 **result 槽(reply[2])**。但 client 的负面
  谓词写成检查 `reply[2]`(应为 `reply[1]`)为 errno,WRITE/READ 又检查 `reply[3]`
  为载荷长度(应为 `reply[2]`)。首个失败点 = 重复 open 期望 EEXIST 落在 reply[2]
  (实际恒 0)→ 谓词为假 → client 提前 sys_exit → marker 不到。
- **为何 commit #2 门禁全绿**:ramfs_server/client 在 commit #2 仅编译(测试未接
  线,boot_ramfs_test 属 commit #3),此逻辑错误只在运行时(T1 首跑)暴露。
- **修复**:全部谓词统一为 `reply[1]`=status、`reply[2]`=result:
  - EOF 读:`r[1]==0 && r[2]==0`;重复 open:`r[1]==USER_ERR_EEXIST`;
  - 坏 fd:`r[1]==USER_ERR_EBADF`;越界写:`r[1]==USER_ERR_EINVAL`;
  - WRITE/READ:`r[1]==0 && r[2]==PAYLOAD.len()`;CLOSE/UNLINK:`r[1]==0`。
- **验证**:修复后 `make test` 从 FAIL 转 **TEST PASS**,三 QEMU 门禁全绿。

### F2(clippy `doc_lazy_continuation`)smp_ramfs_ipc_test doc 注释行首 `+`

- **位置**:`kernel/src/tests.rs`(`smp_ramfs_ipc_test` doc 注释)。
- **触发**:doc 注释某行以 `/// + 阻塞首 recv)` 开头 —— markdown 把行首 `+` 解析
  为**无序列表项**,后续行被视为懒惰续行而缺缩进,`-D warnings` 下
  `doc_lazy_continuation` 报警。
- **修复**:去掉行首 `+`,让句子从上一行自然流动(`连 mem_server 并阻塞首 recv`)。
- **验证**:clippy 重跑零警告。

### F3(门禁纪律)6 处 grep 的 banner 一致性

- T1/T2 各 6 处 grep 逐处核对(Makefile 3 + ci.yml 3);新 banner 插在 M3-3 行之后、
  `! grep -qE "KERNEL PANIC|TRAP:"` 之前,既有 banner 无回归。

## 5. 遗留风险(登记 DEFERRED.md D36-42)

- **D36** 单并发 client:SHM 单窗(4KB,恰两 owner)+ 单连接槽 → 服务端同时只能
  接待 1 客户端(承接 D30)。
- **D37** 每文件单页上限(≤4KB):无页链表/多页管理。
- **D38** 名字内联 IPC ≤ 24B(NAME_MAX=24):长文件名无法表达。
- **D39** EBADF 仅用户协议层复活(USER_ERR_EBADF=MAX-4):内核 syscall 级 MAX-4
  保留空档不复用,统一编码待定。
- **D40** close 保槽 / unlink 按 fd(非 POSIX by-name):多 fd 同名与 by-name
  unlink 语义延后。
- **D41** 无目录树/seek/权限/持久化(平面名空间 + 带 offset 顺序读写)。
- **D42** ramfs 依赖 mem_server 存活(服务链;承接 D32 看门狗)。
- destroy 钩子/revoke 兜底:未 unlink 的文件页经 `process::destroy` 回收,不泄漏、
  无 double-free。

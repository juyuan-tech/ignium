# M2 T1 剩余:每进程独立地址空间 + 用户栈守护页(D20)(2026-08-28)

## 1. 摘要

按 ROADMAP「M2 进行中:T0 ✓ / T1 ✓ → 下一步 T2(IPC)」推进,先补 **T1 剩余**再进入 IPC:

- **每进程独立地址空间(独立 satp + 切换)** —— M2-DESIGN §3.1/§3.2 落地:每进程一份 Sv39 根表(复制内核驻留区,S 权限 U=0),用户页按 U 权限映射到用户 VA 区(L2 索引 1),调度器按线程所属进程切换 satp。
- **用户栈守护页(D20)** —— 用户栈下 4KB 守护页(分配不映射),栈溢出 → 页故障(fail-loudly),而非静默破坏相邻内存。
- 双进程 boot 测试证明隔离:**同一组用户 VA、不同物理页、不同 marker**,若切换 B 进程时未换 satp,B 会在 A 的根表下执行 A 的代码(写 A 的共享页),B 的共享页保持 0 —— 断言即失败。实测通过,`switch_root` 生效。

## 2. 发现明细

### 2.1 用户页映射在内核根表(架构缺口)
- **级别**:架构(M2 T1 的已知缺口,ROADMAP 已标 🔶)
- **位置**:`kernel/src/main.rs:boot_user_thread_test`(旧实现)
- **现状**:T1 阶段 `map_user_page` 把用户页直接映射进 `mmu::kernel_root()`,所有"用户进程"共享同一地址空间、无隔离;线程切换不涉及 satp,无每进程地址空间语义。
- **影响**:进程间无法隔离(任意用户线程可看到/改写他人内存),IPC 与能力模型(T2)无从谈起;用户栈也无守护页(D20)。

### 2.2 用户栈无守护页(D20)
- **级别**:MED(与 2.1 同源)
- **位置**:旧 `boot_user_thread_test` 只映射单页栈
- **现状**:用户栈上方无保护页,越界向下覆盖相邻内存,静默损坏。

## 3. 修复明细

### 3.1 `kernel/src/mmu.rs` —— 根表抽象
- 从 `init()` 抽出 `fn map_kernel_region(root)`(固件 R 超页 / 镜像按段 4KB / 镜像余量 4KB / 尾部 RAM RW 超页 / 栈+陷阱栈 guard unmap / UART 4KB),`init()` 与每进程根表共用。
- 新增 `pub fn create_user_root() -> Result<usize, ()>`:分配清零根页 + `map_kernel_region`,返回根表(不写 satp)。
- 新增 `pub fn switch_root(root_paddr)`:与当前 `satp()` 相同则 no-op;不同才 `csrw satp` + 全量 `sfence.vma`(ISR 内可用:仅 CSR+sfence,零分配)。
- 新增 `pub fn is_mapped(root, vaddr) -> bool`:只读页表走查(L2→L1→L0),不分配、不发 TLB 刷新(守护页/内核区结构性校验用)。

### 3.2 `kernel/src/process.rs`(新模块)
- `Process { id, root }` + `ProcessTable { slots, free }`,`SpinLock` 保护,pid = 槽索引(`MAX_PROCESSES=16`,`free` 留待 T2 销毁复用)。
- `create() -> Result<usize, ()>`:irq_save 下建根表(经 `mmu::create_user_root`)并落表;表满/分配失败返回 Err。
- `root(pid) -> usize`:锁内只读查表;PID 无效 panic(fail-loudly)。

### 3.3 `kernel/src/sched.rs` —— 每进程 satp 切换
- `Thread` 增 `proc: Option<usize>`(所属进程,内核线程 None)+ `root: usize`(应运行的 satp 根表,缓存到 Thread 供 ISR 零分配读取)。
- `spawn_user` 增加进程参数 `proc_id`,`root = process::root(proc_id)`。
- `SwitchTarget` 增 `next_root`;`do_switch` 在 frame_restore/context_switch 前 `mmu::switch_root(next_root)`(汇编恢复路径不碰 satp)。
- `on_tick` 抢占分支在 `self.current = next` 后、返回帧指针前 `mmu::switch_root(threads[next].root)`。
- 内核线程/空闲线程 `root = kernel_root()`,目标为内核线程时自然切回,无需特判。

### 3.4 `kernel/src/main.rs` —— boot 测试重写
- `boot_user_thread_test` 重写:建进程 → 用户页映射到**进程根表**(不再进内核根表)→ 栈守护页(分配不映射,`is_mapped` 校验)→ ecall 往返。banner 不变:`M2 T1: user-mode thread ecall ok`。
- 新增 `boot_process_addrspace_test`:双进程 A/B 共用同一组用户 VA(0x4000_0000 code / 0x4000_1000 shared / 0x4000_2000 守护 / 0x4000_3000 栈),物理页各自独立,marker 不同(A=0xA5 / B=0xB5),流程 get_ticks→写 marker+tick→exit。断言:
  - `shared_a[0]==0xA5 && shared_b[0]==0xB5`(satp 未切换则 B 的共享页为 0);
  - 两 shared[1](tick)非 0(各进程真实执行);
  - `is_mapped` 结构性:守护页未映射、栈页/内核区(UART、0x80000000)已映射、**内核根表不含 0x4000_0000**(用户映射不再污染内核根表)。
  - banner:`M2: per-process address space ok (2 proc @ same VA, satp switch, guard page)`。

### 3.5 门禁同步
- `Makefile` 的 `test` / `test-rva23` 与 `.github/workflows/ci.yml` build job 的 grep 列表各加 `grep -q "M2: per-process address space ok"`(CI 与本地 make 等价)。

## 5. 遗留风险

| # | 风险 | 说明 | 处置 |
|---|---|---|---|
| R1 | 用户进程销毁/页回收未做 | 用户页、进程根表、`free` 槽留待回收;boot 测试保留映射 | T2 每进程生命周期(销毁)时实现 |
| R2 | 内核线程栈(堆分配 16KB)仍无守护页 | D20 仅覆盖用户栈;内核线程栈越界仍可能静默破坏堆 | 已登记 DEFERRED D20 备注,后续按 M2 生命周期处理 |
| R3 | D12 用户故障恢复未做 | 用户访问守护页/非法地址 → 页故障停机(非杀进程);守护页目前只做结构性校验,不行为触发 | T2 用户态异常恢复(D12)实现 |
| R4 | 用户页表内存开销 | 每进程根表 + 内核区 L1/L0 ≈ 20KB;测试 3 进程 ≈ 60KB | 可接受;T3 共享内核表页优化 |
| R5 | 多核下 satp 切换语义 | 当前单核全局 satp + 全局调度器;每核独立地址空间需 D7/D8/D19 | 多核前置(ROADMAP M2) |

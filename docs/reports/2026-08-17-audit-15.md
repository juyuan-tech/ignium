## 2. 修复明细

| # | 级别 | 发现 | 修复 |
|---|---|---|---|
| C1 | CRITICAL | `static PAGE_META`(不可变)经裸指针写 = 形式 UB | 恢复 `static mut`(Rust 可变静态机制)+ 访问一律 `&raw` 不形成引用 + 纪律注释 |
| C2 | CRITICAL | `exit()` 释放**自身正在使用的栈** | 改为 **reaper 回收队列**:exit 移交 Box,idle(在自身上下文)延迟释放 —— 窗口分析显示原方案可工作,但审计正确:drop 自身栈是形式 UB |
| C3 | CRITICAL | **yield_ 合并锁时丢失 `frame_valid=false`**(我的优化引入的回归) | 补回;否则抢占会用过期帧恢复已 yield 线程 |
| C5 | HIGH | **丢失唤醒**:wake 仅在 Blocked 时入队,"唤醒早于阻塞"窗口丢失 | `woken` 标志协议:wake 无条件置位;block_current 消费(继续运行或阻塞),恢复路径清除 |
| C11 | HIGH | **block_current 早退路径:锁未 drop 就恢复中断**(ISR 抢锁死锁) | 先 drop 锁再 irq_restore |
| C8 | HIGH | `unsafe impl Sync` 无 `T: Send` 约束 | `T: Send` 约束 + 内核类型显式 `unsafe impl Send`(单上下文/关中断互斥语义下安全,注释理由) |
| C4 | HIGH | buddy 接受陈旧内页作块头 | 核实:内页 meta 恒为 `(order,false)`,free 已拒绝;驳回(附分析) |
| C6 | HIGH | Condvar::wait 释放锁不唤醒互斥等待者 | 驳回:经典 pthread 语义(条件不满足,唤醒互斥等待者无意义;真正 unlock 会唤醒);补注释 |
| C7 | HIGH | 抢占不能恢复 yield/block 线程;自检不证明抢占 | 已由 frame_valid 协议处理(设计如此,非 bug);自检已 tick 驱动(150ms>片) |

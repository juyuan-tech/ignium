# 报告:M1 性能优化轮(2026-08-17)

## 1. 摘要

M1 收官后的性能优化:4 项改动 + 性能基线落地。

## 2. 优化明细

| # | 优化 | 内容 | 收益 |
|---|---|---|---|
| P1 | **SSTC 直写 stimecmp** | 定时器重排从 SBI ecall(M 模式往返,数百周期)改为直接 `csrw stimecmp`;QEMU virt 与 RVA23 平台均支持 | 每 tick(100Hz)省一次 ecall;中断路径最大单项 |
| P2 | **堆基址缓存** | `slab_class_of`/`dealloc` 原来每次经 `mem::base()` → 分配器锁;改为 `heap::init()` 缓存一次,`AtomicUsize` 读取 | 每次 alloc/dealloc 少一次锁获取 |
| P3 | **调度器单锁** | yield_/block_current/exit 原来两次取 SCHED 锁(状态+指针);合并为一次 | 每次切换少一次锁往返 |
| P4 | **性能基线** | `heap::bench`(64B 档 100k 次分配/释放)+ `sched::bench`(双线程乒乓 4000 次切换),启动打印 | 后续优化有对比数据 |

另:清理了被 SSTC 取代的 SBI 路径(保留为回退实现,标注 dead_code)。

## 3. 实测基线(QEMU virt,TCG 模拟)

```
[000015] [INFO ] bench: slab 64B alloc+dealloc ≈ 17 ns/op
[000015] [INFO ] bench: context switch ≈ 199 ns/op (yield path)
```

- slab 17ns/op:含堆锁 + 档索引 + 链表弹出/压回,已是高效路径。
- 上下文切换 199ns/op:含 irq_save/restore + 调度锁 + 15 寄存器
  保存/恢复 + 就绪队列操作。
- 注:TCG 模拟下数值为相对基线;真机(标量核,更高主频)预期更低,
  KVM/QEMU 加速下另有差异。数值随代码变更对比即可。

## 4. 验证

- 门禁:dev+release / clippy / fmt / make test / test-smp 全绿。
- 定时器(SSTC 直写)在 ISR 与 boot 两处工作正常(uptime 持续)。

## 5. 后续优化候选(记录)

- 中断快速路径(D1):非切换 tick 免全寄存器保存 —— 收益 ~100ns/tick,
  风险中等,列入 M1.5/压力自检后再评估。
- 互斥锁公平化(M2)。
- 日志 IRQ 驱动输出(115200 下 UART 轮询为主,收益大但需中断驱动)。

# 报告:M1 代码优化 + 初步自审(2026-08-17)

## 1. 摘要

对 M1 现状代码(satp 切换后的 trap/定时器/buddy/mmu 组合)进行审计驱动的优化:
- 修复上轮外部审计 L3 遗留的分配器多别名隐患(`&'static mut` 每次新建)
- 消除页表初始化路径的冗余 volatile 屏障
- 其余路径审查后确认已处于该阶段合理形态,不做为优化而优化

## 2. 自审发现明细

### 2.1 实质性优化(已实施)

| # | 发现 | 处置 |
|---|---|---|
| O1 | `allocator()` 每次调用返回新 `&'static mut`(审计 L3:理论别名 UB;未来加锁缺唯一加锁点) | 重构为 `with_allocator(闭包)`:一次操作恰好一个 `&mut`,并为调度器里程碑的锁预留唯一入口 |
| O2 | `zero_page` 用 volatile 写(页表初始化无并发读者,裸指针写编译器不可消除) | 改非 volatile `ptr::write`,少一道编译器屏障 |

### 2.2 审查确认无需改动(多视角)

- **数据流**:satp 切换后身份映射下 buddy/mmu/uart 地址不变,无重定位风险;
  分配器元数据与块内容解耦,`with_allocator` 重构后调用点语义不变。
- **并发/重入**:定时器 ISR 仅 `tick_up`+`fetch_add`+ecall,零日志 ✓;
  `with_allocator` 是"关中断外主上下文"使用的单例访问,语义与重构前一致。
- **性能**:ISR 路径(31 GPR 保存/恢复)对当前阶段可接受;UART 每字符
  2×fence 相对 115200 波特(≈87µs/字符)可忽略。
- **安全**:`free` 的界检查/内页拒绝/链表断言(MED#4)在重构后保持。

### 2.3 延迟优化项(记录,不实施)

| 项 | 说明 | 计划 |
|---|---|---|
| 中断快速路径 | timer ISR 保存 31 GPR + 4 CSR,可用"仅保存调用者保存寄存器"的快路径降低延迟 | M2(调度器前) |
| 页权限拆分 | RAM 整体 RWX → 代码 RX / 数据 RW | M1.5 |
| 分配器加锁 | 单核假设 → 调度器/SMP 时用 `with_allocator` 统一加锁点 | 调度器里程碑 |
| 栈守护页 | boot/trap 栈无守护页 | M1.5(MMU 已就绪) |
| 日志批量输出 | 每字符 2×fence 的写路径可合并(收益 <0.1%,暂不做) | 性能基准出现后 |

## 3. 验证结果

- 门禁:`cargo build`(dev+release)/ `clippy -D warnings` / `fmt --check` / `make test` 全绿。
- 行为回归:buddy 自检、Sv39 自检、uptime 心跳全部正常(重构不改变语义)。

## 4. 遗留风险

- `with_allocator` 未来加锁时,ISR 内分配(如 trap 需要页表页)会与主上下文
  死锁 —— 加锁里程碑需同时引入"IRQ 安全分配"设计(延迟到紧急栈之后)。

# M2 T2b 报告:优先级继承(PIP)+ IPC 压力测试

- 日期:2026-08-28
- 阶段:M2(微内核骨架)子任务 T2b(优先级继承 + 压力测试)
- 提交:`feat: M2 T2b - priority inheritance (PIP) + IPC stress test`

## 1. 摘要

M2 T2 按 `docs/M2-DESIGN.md` §9 分 T2a/T2b 两拍落地,本次完成 **T2b**:

- **优先级继承(PIP)**:T2a 已落地同步 IPC 阻塞配对,但存在经典优先级
  反转 —— HIGH 接收方阻塞在 IPC,等待 LOW 进程线程来 send/recv 配对;
  若存在 MED 忙循环,把 LOW 饿死,HIGH 永久阻塞。本次引入**按进程捐赠**:
  阻塞方把其**有效优先级**捐赠给期望对方进程的所有线程,被捐赠线程
  得以抢占中间优先级忙循环、完成配对、唤醒等待方;配对完成撤销捐赠。
  调度器新增 `Donation` 表 + `eff_prio`(有效优先级,`enqueue` 选队用)
  + `register_donation`/`revoke_donations`/`requeue_proc_threads`;
  `on_tick` 改用**有效优先级**判当前线程抢占资格(被抬升者不被中间
  优先级打断);`ipc_wake_with_msg` 唤醒即撤销捐赠。
- **内核线程 IPC 消息路径补全**:`ipc_wake_with_msg` 原只写 TCB **帧**
  (用户线程经 frame_restore 读取);内核线程经 `block_current`(ctx 恢复)
  读不到帧 → 收不到消息。本次 `Thread` 增 `ipc_msg` 字段 +
  `take_ipc_msg()`,唤醒同时写帧与 ipc_msg,内核线程模式取消息即清。
- **IPC 压力测试**:引导期内核线程 send/recv 环 1000 次(替代手工汇编
  用户程序,避免编码错误风险),断言消息完整到达、无丢失无死锁、和值
  正确;每次 NoPeer/配对各跑一遍捐赠 register/revoke,捐赠机制一并受压。
- 附带:DEFERRED D22 状态修正(→ 已实现,落地 sched.rs,T2a)。

**不做的**(遗留,见 §5):多级捐赠链的完整语义(本机制自然支持单跳 +
近似链)、捐赠与用户态 Mutex 结合、万级(≥10k)压力(归 T4)、多核 IPC。

## 2. 发现明细

### 2.1 优先级反转(缺陷,本次修复)

- **级别**:功能缺陷(IPC 语义:等待方被饿死 → 永久阻塞,非死锁但等效)。
- **位置**:`kernel/src/ipc.rs` NoPeer 分支 + 调度器优先级模型。
- **触发条件**:HIGH 线程 H 阻塞等待 LOW 进程 L 的线程配对;MED 线程 M
  忙循环。无 PIP 时 L 滞留 LOW,被 M 饿死 → H 永不完成(优先级反转)。
- **影响**:系统功能挂起;这是同步 IPC 的必解问题(M2-DESIGN §5.1 明确
  要求优先级继承)。

### 2.2 内核线程 IPC 收不到消息(缺陷,本次修复)

- **级别**:功能缺陷(消息投递路径不完整)。
- **位置**:`kernel/src/sched.rs` `ipc_wake_with_msg` / `block_current`。
- **触发条件**:内核线程(非用户线程)经 `block_current` 阻塞在 IPC,
  被配对唤醒后经 ctx 恢复 —— 消息写在 TCB **帧**,ctx 恢复路径读不到。
- **影响**:内核线程做 IPC 收方时消息丢失(用户线程 frame 路径正常)。
  压力测试选择内核线程实现,顺带暴露并修复。

### 2.3 设计陷阱:抬升置 woken 会破坏丢失唤醒协议(设计修正)

- **级别**:设计缺陷(实现过程中发现并规避)。
- **位置**:`sched.rs` `requeue_proc_threads`(草案曾置 `woken=true`)。
- **根因**:草案按「M6 陈旧 woken 属良性虚假继续」在抬升时置
  `woken=true`,使 ctx-only 线程可被抢占。但 M6 良性结论仅适用于
  Mutex/Condvar 循环(重查重等);**IPC 的 recv/send 在 `block_current`
  之前已登记 pending** —— block_current 一旦消费陈旧 woken 而跳过阻塞,
  该 pending 即成孤儿,下次配对唤醒时 `debug_assert!(state==Blocked)` 失败。
- **决定**:抬升**不触碰 woken**。抢占资格由恢复机制决定:新线程
  frame_valid、IPC 配对唤醒的 ctx 线程经协作路径(`pick_next(true)`)选中;
  当前内核 IPC 用户(用户线程 frame 路径 + 测试内核线程协作路径)均不
  需要"被捐赠 ctx-only 线程的 on_tick 抢占"。若未来 M3 内核服务线程
  出现该场景,再以"仅对 frame 无效线程抬升 woken"方式收敛。

### 2.4 自检期 main(idle)SIE 恒为 0(开发实证,同 T2a)

- **级别**:测试环境陷阱(非内核缺陷)。
- **现象**:self_test 第 6/7 项阶段 2 需纯自旋等待(排除协作路径假阳性),
  但 idle 上下文 SIE=0,定时器不触发,被自旋独占 CPU 的线程永不运行。
- **对策**:阶段 2 显式 `arch::irq_enable()`(D22 已验证该模式)。

## 3. 修复明细

### 3.1 sched.rs:3 级优先级 + 捐赠表 + 有效优先级

- 优先级 2 级 → 3 级:`PRIO_LEVELS=3`,新增 `PRIO_MED=1`,`PRIO_LOW=2`;
  `ready: [VecDeque; PRIO_LEVELS]` 补第 3 队;既有 HIGH/LOW 相对序不变。
- `Donation { donor_tid, peer_proc, prio }` 表(`MAX_DONATIONS=MAX_THREADS`,
  init 预留容量,ISR 只读零分配)。
- `eff_prio(id)` = 自然优先级与指向所属进程的捐赠取最小(数值小 = 高)。
- `enqueue` 改用 eff_prio 选队 → spawn/spawn_user/requeue 一律经 enqueue,
  捐赠对"晚 spawn 的接收方"自动生效。
- `on_tick` 当前线程优先级改用 **eff_prio**:被抬升线程运行期间,中间
  优先级不得抢占它(否则 PIP 失效)。
- `requeue_proc_threads(proc)` 重排该进程全部就绪线程到有效优先级队列。
- `register_donation(donor, peer)` / `revoke_donations(donor)`(配对完成
  `ipc_wake_with_msg` 内调用)。
- 公开 API:`donate_on_block`(ipc.rs NoPeer 分支调用)、`take_ipc_msg`、
  `spawn_owned`(内核线程挂到进程,供 PIP/压力测试)、`donation_count`
  (测试断言捐赠清空)。

### 3.2 sched.rs:`Thread.ipc_msg` + 内核线程收消息

- `Thread` 增 `ipc_msg: Option<[usize; MSG_WORDS]>`(三处构造补 `None`)。
- `ipc_wake_with_msg`:msg=Some 时同时写帧与 `t.ipc_msg`;唤醒即
  `revoke_donations(tid)`。
- `take_ipc_msg()`:当前线程读取即清(仅内核线程模式使用)。

### 3.3 ipc.rs:NoPeer 分支登记捐赠

- `send` NoPeer:登记 pending 后、返回前 `sched::donate_on_block(tid, dst)`
  —— 把期望接收方进程 `dst` 抬到发送方有效优先级(发送方等对方来 recv
  的反转场景)。
- `recv` NoPeer:对称,`donate_on_block(tid, src)`。
- 锁序不变:捐赠注册在 IPC 锁释放后、阻塞前(无调度点,原子性保持)。

### 3.4 回归测试

- `sched::self_test` 第 7 项 PIP(确定性反转):H(HIGH)recv 阻塞 → 捐赠
  注册;L(LOW)忙循环 3 tick 后 send 配对(被抬升到 HIGH 先于 MED 运行);
  M(MED)忙循环 50 tick 制造饿死窗口。断言 H 完成 tick < M 完成 tick
  (无 PIP 时 L 被 M 饿死,H 永不完成 → 超时失败)+ 消息完整 + 捐赠表清空。
  banner:`M2 T2b: priority inheritance ok (PIP)`。
- `tests.rs::boot_ipc_stress_test`:进程 pa/pb 互授 cap;内核线程 sender
  (spawn_owned→pa, HIGH)发 1000 条 `[BASE+i,0,0,0,0]`,recver(spawn_owned
  →pb, HIGH)收,校验 `m[0]==BASE+i` 并累加和。断言配对数到齐、和 ==
  等差数列和(消息无丢失无损坏)、捐赠表清空。
  banner:`M2 T2b: IPC stress ok (1000 pairings, sum ok)`。

## 5. 遗留风险

1. **多级捐赠链近似**:`register_donation` 存 donor 的**有效**优先级,被
   抬升线程再捐赠时天然传递 → 支持单跳 + 近似链;但无"主动提升传播
   完整性"校验(如环形捐赠检测、链长上限)。捐未配对的 peer 永不来的
   场景,捐赠永续(表上限 = 线程上限,有界)。
2. **被捐赠 ctx-only 线程的抢占**:抬升不置 woken(见 §2.3),若未来出现
   "被捐赠的内核 ctx-only 线程被 MED 忙循环饿死"场景,需按"仅对
   frame 无效线程抬升 woken"或等价机制收敛。当前用户线程(frame 路径)
   与测试内核线程(协作路径)均不受影响。
3. **万级压力归 T4**:当前 1000 次配对;≥10k 级压力(消息速率/延迟基准)
   待 T4。
4. **多核 IPC 语义**:捐赠表为全局单表,多核每核独立调度时语义需重审
   (D7-D9 前置)。
5. **woken 标志**:抬升不触碰 woken,协作路径消费不变;既有 D22 语义不受
   影响。

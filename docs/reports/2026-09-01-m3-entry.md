## 2. 发现明细

### F1(M3 T3 bring-up 实测,已修)守护页解映射破坏身份映射不变量

- **级别**:HIGH(启动即故障,`make test` 崩溃)。
- **位置**:`kernel/src/mmu.rs`(新增 split_superpage/unmap 路径)。
- **触发**:`alloc_free_stack` 分配 20KB 栈并 unmap 守护页后,该 PA 被 buddy
  复用作**页表页**;`ensure_table` 对其 `zero_page`(memset)时身份映射已缺失。
- **现象**:`scause=0xf`(store page fault)@ `sepc=0x802059b6`,`stval=0x86041000`
  (守护页 PA);反汇编定位到 `zero_page` 内联 memset 紧随 `alloc_pages`。
- **根因**:内核恒经 VA==PA 访问物理页,unmap 守护页后不恢复即把该 PA 从身份
  映射中移除;"归还前保持解映射以免陈旧 PTE"的思路对身份映射不成立。

### F2(单核 `make test` 偶发,~4%,已修)T3b 亲和槽竞态

- **级别**:MED(偶发 KERNEL PANIC,门禁误判)。
- **位置**:`kernel/src/tests.rs:1131`(`smp_thread`)。
- **现象**(复现 dump):
  ```
  location: kernel/src/tests.rs:1131:5
  message: index out of bounds: the len is 4 but the index is 18446744073709551615
  ```
  (`SMP_SLOT_HART` 长度 = MAX_HARTS = 4,索引 = `usize::MAX`)。
- **根因**:`smp_sched_test` 于 `irq_enable` **之后**运行;主线程
  `spawn(smp_thread, PRIO_HIGH)` 后,新线程即就绪入队。定时器中断可在
  `spawn` 返回与 `SMP_TARGET_HART[tid].store(h)` 之间抢占主线程并调度
  高优先级 `smp_thread`,后者读到未初始化的 `usize::MAX` 哨兵 → 越界 panic。
- **为何 T3 前偶发**:该窗口(数条指令)一直存在;T3 的 `alloc_free_stack`
  内新增 `split_superpage`(取页+建 L0+sfence)改变 spawn 耗时,使 `irq_enable`
  后首个定时器 tick 相位落在窗口内。

### F3(SMP `make test-smp` 偶发,~6%,已修)ccsd shootdown 完成轮询竞态

- **级别**:MED(偶发断言失败 KERNEL PANIC,门禁误判)。
- **位置**:`kernel/src/tests.rs:1374`(`smp_shootdown_phase`)。
- **现象**(复现 dump):
  ```
  location: kernel/src/tests.rs:1374:5
  message: ccsd: B must be killed by D12 after revoke
  ```
  前一行 `D12: user fault scause=0xd sepc=0x4000000c stval=0x50000000` 表明
  B 已故障且杀进程已启动。
- **根因**:`kill_process` 在**入口**即 `FAULT_KILL_COUNT.fetch_add(1)`
  (`kernel/src/sched.rs:1445`),而 `process::destroy` 在路径**末尾**完成。
  跨核场景下 boot hart 轮询 `fault_kill_count()` 只能证明"杀进程已启动",
  可能撞上"计数 +1 而目标核 destroy 未结束"窗口 → `pid_root(b_pid)` 仍
  `Some` 误判未死。
- **为何偶发**:目标核 destroy(含 switch_root + 页回收)耗时与 boot hart 轮询
  频率的相对时序;T3 的 drop 路径新增 `remap_kernel_4k`(一次 superpage 拆分
  检查)微调了该窗口。

## 3. 修复明细

### R1(对 F1)守护页归还前恢复身份映射再 dealloc

- `kernel/src/sched.rs`:`KernelStack` 布局改 `Layout::from_size_align(
  THREAD_STACK_SIZE + STACK_GUARD_SIZE, PAGE_SIZE)`(20KB,页对齐);
  `alloc_free_stack` 分配后 `unmap_kernel_4k` 守护页;`Drop` 先
  `remap_kernel_4k` 恢复守护页映射再 `dealloc`(同 Layout,防 alloc/dealloc
  不匹配 UB)。
- `kernel/src/mmu.rs`:新增 `split_superpage`(2MB superpage leaf → 512 个
  4KB leaf,幂等)/ `unmap_kernel_4k` / `map_kernel_4k` / `remap_kernel_4k`
  (带单地址 `sfence.vma`);身份映射不变量下"恢复"即正确语义。

### R2(对 F2)`smp_thread` 自旋等亲和槽写就绪

- `smp_thread` 改为先 `while SMP_TARGET_HART[tid] == usize::MAX { spin_loop() }`
  再读 target。主线程写槽恒会完成(循环内不 yield),自旋必然终止。

### R3(对 F3)ccsd 同时轮询完成条件

- 等待条件由 `fault_kill_count() == kill_before` 改为
  `fault_kill_count() == kill_before || pid_root(b_pid).is_some()`:
  同时等待"杀进程已启动"(证明 B 故障、TLB 已刷)与"进程已销毁"
  (证明 kill 完成),二者都满足才通过。保留最终 `pid_root.is_none()` 断言。

- 五门禁全绿:clippy `--release -D warnings` / `fmt --check` / `make test` /
  `make test-smp` / `make test-rva23`(exit=0);dev + release 双 profile 可编。
- 三 log(单核 / smp / rva23)均 **0** 条字面 `KERNEL PANIC|TRAP:`,且
  `M3 T1: ELF loader ok (user ELF ran)`、`M3 T2: cross-core kill/shootdown ok`
  、`M3 T3: kernel thread stack guard page ok` banner 齐全(M3 T2 单核退化为
  N=1 仍打印)。
- 稳定性(修复后连跑):单核 **58** 连跑、SMP **26** 连跑无故障;修复前单核
  ~4%、SMP ~6% 偶发 KERNEL PANIC。
- M3 T3 自检断言:守护页分配后 `is_mapped==false`、栈体 `is_mapped==true`、
  drop 后守护页恢复映射(身份映射不变量)。

## 5. 遗留风险

- **带 proc 内核线程的栈守卫**(DEFERRED D27):内核线程栈守护页仅在
  `kernel_root` 生效;带进程根表运行时须跨根表拆分传播。当前内核线程均
  proc=None,守卫生效;引入带 proc 内核线程时落实。
- **SCHED 全局锁拆分**(D25)、**D1 中断快速路径**(D1)、**slab 水位扫描**
  (D26):M3 入口评估后延后(M4),评估理由见 M3-DESIGN §7 与 DEFERRED.md。
- 其余 M2 已知限制(多核 IPC 跨核语义、FDT 单 bank、自发自收阻塞)保持,
  见 docs/DESIGN.md"已知限制(截至 M3 入口收官)"。
- M3 用户态服务(uart_server → 内存服务 → ramfs → spawn 服务化)为阶段 3
  下一步工作(ROADMAP.md 阶段 3 表格),内核侧只交付了 `spawn_elf` 等原语。
